# Social publishing migration (n8n -> Supabase Edge Functions)
Move instant and scheduled publishing to LinkedIn and Instagram from the n8n workflows "Publicación inmediata" and "Publicación programada" to Supabase, with one shared pipeline, one publisher per network and full user feedback.
Branch: feat/social-publishing-foundation (from main cb52d3d). Phase 1 authorized only. No push/PR/merge or production change without explicit user approval. n8n stays live until the cutover phase.

## Specs
S1. "quiero que el usuario reciba feedback de todo para saber cuando ha ido bien y cuando ha ido mal algo y saber el motivo, incluso la opción de resolverlo en el momento que sepa del error y reintentar la publicación habiendo corregido el error o simplemente reintentando porque en ese momento algo ajeno al proyecto haya fallado"
S2. "me parece bien una parte compartida y después cada uno con su publicador" — one shared core (authorization, content, claiming, aggregate state) and one publisher per network; each selected network is one target with its own state, attempts, error and post id; instant and scheduled share the same pipeline.
S3. "Me parece bien cambiar el API de Linkedin para estar lo más actualizado posible" — LinkedIn /rest/posts + Images API with a current Linkedin-Version; Instagram on a current Graph API version.
S4. "mira la documentación oficial de linkedin y meta para cumplir con los requisitos de las publicaciones" — enforce the official requirements recorded in L6.
S5. Images: user crops in the publish configuration to each network's requirements (L4: "me gusta la idea de dar al usuario la oportunidad de recortar desde el mismo dashboard y adaptar la imagen a las exigencias de la red social en cuestion"); a non-compliant image blocks that network until fixed; derivative JPEG per network, original untouched (L5: "creo que lo mejor en ambas cuestiones es la opción A").
S6. Tokens server-side only, refreshed where possible, expiry checked when scheduling, user warned before expiry and on failure ("token caducados (el usuario no lo sabía ya que no le informamos de eso)").
S7. Text: one shared sanitizer plus per-network escaping; no literal "\n" or broken quotes ("las descripción se publicaban con caracteres extraños (por ejemplo las "" o aparecían un /n en medio del texto)").
S8. Video and Instagram Reels are phase 2 ("Quiero también evolucionar y poder publicar videos (en instagram incluso hacer reels)"); the data model already distinguishes media format.
S9. "Para el punto 1, guardamos el momento real tal y como recomiendas" — store the real instant (Madrid wall-clock converted to UTC) and display in Europe/Madrid; convert existing rows once at cutover.
S10. "los avisos por email podemos usar resend (es lo que ahora mismo está implementado)"
S11. Never publish the same target twice: an uncertain outcome becomes needs_action, never an automatic repeat.
S12. Keep the legacy projection (state, instagramResult, linkedlnResult with "true"/"false"/"notSelected", "scheduled"/"published") until the client is migrated.
