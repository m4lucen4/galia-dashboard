# Multimedia image move — implementation tasks

**Repository locator:** `odd/tasks/multimedia-move-images.md`
**Branch point:** `feat/multimedia-move-images` at `c1bbf6b`.
**Objective:** Let a user move multiple unlinked images from the multimedia library to any existing nested folder through an explicit Move → destination picker → Confirm flow.
**Problem / why:** `moveItems` currently starts all storage moves concurrently, has no collision or project-reference guard, and the slice updates paths optimistically while retaining stale public preview URLs. The multimedia screen does not expose a move flow.
**Authorized roots:** `odd/tasks/multimedia-move-images.md`, `src/redux/actions/MultimediaActions.ts`, `src/redux/slices/MultimediaSlice.ts`, `supabase/functions/move-user-media/**`, `src/features/multimedia/**`, and `src/locales/{es,en,cat}/translation.json`, plus the minimal local Edge Function configuration required by that function. The UI and locale roots are pre-authorized only for MMI-02; MMI-01 must not edit them. Do not edit unrelated sources, existing user changes, or configuration.
**Scope:** MMI-01 is authorized to expand the local backend with an authenticated, server-side preflight-and-move Edge Function. It covers image files only; multi-selection; existing folders at any depth as destinations; collision prevention; linked-image alert data; project-linked image protection; compensating failure handling; and authoritative refresh of displayed files and previews. Drag-and-drop is out of scope. Folder moves, destination-folder creation, overwrites, new dependencies, tests, remote operations, and changes to unrelated multimedia actions are out of scope.
**Constraints:** The `user-media` Supabase Storage bucket represents folders implicitly, preserving empty folders with `.keep`; ignore `.keep` as a selectable item and never move or delete it as part of this feature. The Edge Function authenticates the caller and binds every source and destination to that caller's `{userId}/` prefix. It allows `/` and existing nested folders, but rejects `/proyectos` and all descendants as protected project media in either direction. Its service-role preflight fails closed when it cannot inspect `projects.image_data`, `project_photos.supabase_url`, or `projectsPreview.image_data`. Linked sources return a non-leaking structured `referenced` error. A collision, invalid path, missing nested destination, duplicate target, or reference cancels the request before mutation. Move sequentially and compensate in reverse after a failure, preserving the original error and rollback details in a `partial` result. Revalidate immediately before moving; Storage and database checks remain non-atomic, so no atomic no-overwrite guarantee is claimed. Treat server results and post-operation reloads as authoritative; do not retain an optimistic URL/path mapping. Keep the existing Spanish UI/i18n convention. No tests: project `AGENTS.md` says no test suite and prohibits test files.
**Route / delegation:** `delegated` — 2+ nontrivial files; read-prep required. Read the current multimedia action, slice, screen, toolbar/grid, project image URL shape, translations, and existing dirty-worktree boundaries before implementation.

## Acceptance criteria

- Multiple eligible images can be selected and moved as one confirmed batch.
- The destination picker can select any existing nested folder, including the library root.
- Cancelling before confirmation does not call the move operation or mutate Storage.
- Existing destination names and duplicate names within the selected batch cancel the batch before any move; no overwrite occurs.
- Images referenced by known project URL sources are excluded/protected through authenticated, service-role reference checking, not assumed RLS behavior, and the client can alert without exposing other users’ data.
- A batch failure attempts reverse compensation for completed moves, communicates the original and any compensation failures, and reloads authoritative state.
- Success and failure both refresh the visible listing so paths and image previews are current.
- Focused ESLint for touched files and `pnpm build` pass before delivery; full `pnpm lint` is a known baseline failure of 38 errors and 9 warnings outside this feature; no tests or dependencies are added.
