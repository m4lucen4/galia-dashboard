# Social video publishing (Instagram Reels and Stories, LinkedIn video)
Videos become project media, are selected when publications are generated from a project, and are published by the existing Edge Function pipeline.
Branches: one per phase from updated main (`git switch -c <branch> --no-track origin/main`). Production migrations only with explicit user approval.

## Specs
- S1. User request: "Me han solicitado la opción de publicar videos en linkedin e instagram (aquí sería hacer reels e incluso histories)".
- S2. Videos belong to the project, not to the publication: "rompe la mecánica del proyecto de crear el contenido desde proyectos y de ahí generar publicaciones para redes sociales". The video is uploaded in the project, selected when publications are generated, and the publication configuration only chooses the format per network (Instagram: Reel or Story; LinkedIn: video).
- S3. Videos live in their own table and bucket in Supabase Storage, never inside `image_data`. A video lives while it stays in the project; deleting the video or the project removes the stored file.
- S4. Per-video limit: "ponemos tope por video, podemos probar con 300mb y 15 minutos". No per-plan quota for now; video size is stored so a quota can be added later.
- S5. "un solo video por publicación, esto no es un canal de youtube es para publicaciones en instagram y linkedin".
- S6. First delivery covers Instagram Reels, Instagram Stories and LinkedIn video. Out of scope: server-side transcoding, mixed photo/video carousels, music, stickers.
- S7. Validation happens in the browser before upload (format MP4/MOV, size, duration, aspect ratio) with clear Spanish messages; a poster frame is captured client-side and used as thumbnail so the dashboard does not load whole videos.
- S9. "Si, solo mp4 y limite de subida de 300mb": only MP4 (`video/mp4`, `.mp4`) is accepted; the size cap is 300 MB (300000000 bytes) and the project upload limit is 300 MB. Message for other formats: "Exporta el vídeo en MP4 (en iPhone: Ajustes → Cámara → Formatos → Más compatible)".
- S8. Publishing never publishes twice: the existing irreversible-step protection applies to video; Instagram processing is polled across worker runs without blocking; LinkedIn upload is chunked without loading the whole video into memory.

## T1 contract (shared by the server and client writers)
- Table `public.project_videos`: `id uuid pk default gen_random_uuid()`, `project_id bigint not null references public.projects(id) on delete cascade`, `storage_path text not null unique` (`<project_id>/<id>.mp4`, must start with the row's project_id), `poster_path text null` (`<project_id>/<id>.jpg`), `original_name text not null` (1-255 chars), `bytes bigint not null` (75000-300000000), `duration_ms integer not null` (3000-900000), `width integer not null > 0`, `height integer not null > 0`, `faststart boolean not null` (moov atom before mdat), `position integer not null default 0`, `created_by uuid null default auth.uid()`, `created_at timestamptz not null default now()`. Index on `(project_id, position)`.
- RLS: select/insert/update/delete for `authenticated` when the caller is admin, project owner (`projects."user"`) or assigned editor (`projects.assigned`), through a new null-safe `private.project_media_allowed(p_project bigint)` helper. No anon access. Insert/update also require `storage_path` and `poster_path` to start with `<project_id>/`.
- Bucket `project-videos`: public (Instagram downloads `video_url` from a public URL), `file_size_limit 300000000`, `allowed_mime_types ['video/mp4','image/jpeg']`. Storage policies insert/update/delete/select for `authenticated` through `private.project_video_path_allowed(name)`: name matches `^([1-9][0-9]{0,17})/[0-9a-f-]{36}\.(mp4|jpg)$` and the caller may edit that project. Direct SQL deletes on storage.objects are not allowed, so the client removes the objects (video and poster) before deleting the row, and `deleteProject` removes every object under `<projectId>/` in `project-videos` before deleting the project.
- Client upload: resumable TUS (`tus-js-client`) to `<SUPABASE_URL>/storage/v1/upload/resumable`, chunk size 6 MB, `x-upsert: false`, progress shown; the client generates the uuid, uploads the video and the poster, then inserts the row; if the insert fails it removes the uploaded objects.
- Client validation before upload (blocking, Spanish messages): MP4 only (S9), size <= 300000000, duration 3 s-15 min, readable metadata. Non-blocking: `faststart` false shows a warning that Instagram may reject the video. Poster: frame at ~1 s (or 0 for shorter videos) drawn to canvas, JPEG.
